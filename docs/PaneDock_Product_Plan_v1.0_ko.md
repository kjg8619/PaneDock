## 1. 문서 개요

> **제품의 한 문장 정의**
>
> 사용 중인 터미널의 포커스된 작업 영역을 따라 Dock의 대상을 바꾸고,  
> 이후 그 경로에 연결된 프로젝트 도구 묶음으로 확장한다.

| **문서 기준** | **내용** |
| --- | --- |
| **기준일 / 버전** | 2026년 9월 16일 / 기획 문서 v1.0 |
| **현재 단계** | 아이디어 정리 및 구현 검증 전. 완성된 앱이나 지원 확정 목록이 아니다. |
| **핵심 방향** | 포커스·경로 추적을 먼저 완성하고, 프로젝트별 도구 연결은 다음 단계로 확장한다. |
| **제품명** | PaneDock은 가칭이다. 최종 이름·상표·도메인은 미확정이다. |

### 이번 문서에서 고정하는 방향

초기에는 프로젝트 등록 없이 동작한다. 현재 폴더 열기와 경로 복사처럼 작은 기능으로 실제 작업을 보조한다. 기존 macOS Dock은 변경하지 않고, 별도 Dock UI로 공존한다.

확장 이후에도 포커스 추적은 제품의 중심으로 남는다. 프로젝트 도구 묶음은 다른 제품으로의 전환이 아니라, 감지한 작업 위치 위에 쌓는 기능이다.

| **0.1 포커스 추적** | **0.2 안정화·연동 확대** | **0.3 프로젝트 연결** |
| --- | --- | --- |
| **한 환경의 선택된 pane을 정확히 따라가는 최소 Dock** | 실사용 오류를 줄이고 연결 모듈을 하나씩 추가 | 경로에 이름·링크·폴더· 앱의 실행 대상을 연결 |

## 2. 제품 정의와 개발 원칙

### 출발점과 해결하려는 문제

대상은 Terminal, Ghostty, cmux 등의 환경에서 TUI 중심으로 작업하는 사용자다. 핵심 요구는 Dock에서 프로젝트를 다시 선택하는 것이 아니라, 이미 선택한 pane의 작업 위치에 맞춰 Dock이 자연스럽게 바뀌는 것이다.

첫 단계에서 검증할 것은 추적의 정확성과 작은 편의 기능이다. 다음 단계에서는 프로젝트의 저장소·문서·미리보기 페이지를 다시 찾는 일을 줄이는지 확인한다. 두 단계의 성공을 같은 것으로 취급하지 않는다.

> **합의된 발전 방향**
>
> “어디에서 작업하는지 따라오는 Dock”에서 시작해,  
> “거기서 필요한 것을 준비해주는 Dock”으로 확장한다.

### 기획에서 사용하는 용어

| **용어** | **이 문서에서의 의미** |
| --- | --- |
| **포커스된 pane** | 사용자가 현재 선택한 작업 영역. 터미널별 pane·surface·tab을 공통 개념으로 정규화한다. |
| **작업 경로(CWD)** | 연동 모듈이 보고한 현재 작업 디렉터리. 편집 중인 파일 경로나 TUI 내부 프로젝트와 같다고 가정하지 않는다. |
| **현재 작업 정보** | 앱·창·세션·pane 식별자, 머신, 경로, 포커스와 갱신 상태를 묶은 정보. |
| **프로젝트** | 0.3에서 도입할 사용자 정의 묶음. 기준 경로, 이름, Dock 항목을 가진다. |
| **연결 모듈(Adapter)** | Ghostty·cmux 등 환경별 정보 수집을 담당한다. Dock의 화면과는 분리한다. |

### 설계 원칙

정확성 우선. 가장 최근에 들어온 경로가 아니라, 현재 포커스된 대상의 유효한 경로를 사용한다. 정보가 없을 때는 추측보다 상태 표시를 택한다.

작업 방해 최소화. Dock은 터미널의 입력을 가로채지 않고, 브라우저로 이동했을 때도 마지막 작업 위치를 유지한다. 자동 전환으로 앱·명령을 실행하지 않는다.

작은 시작과 분리된 구조. 첫 환경 하나에서 전체 사용 흐름을 완성한다. 프로젝트 관리·위젯·확장 플랫폼을 먼저 만들지 않되, 나중에 붙일 수 있도록 감지와 표시를 분리한다.

구분 원칙: 제품의 방향은 대화에서 합의된 내용이다. 이 문서의 상세 UI, 수치, 구현 구조는 개발을 위한 제안이며, 실기기 결과에 따라 조정한다.

## 3. 단계별 로드맵과 우선순위

| **단계** | **개발 범위** | **완료·진입 기준** |
| --- | --- | --- |
| **검증 단계** | 설치 버전·권한·연동 기능 확인. 앱·pane·경로·정보 출처를 보여주는 진단 화면. | 포커스 변경과 경로 변경을 구분하고, 비활성 pane의 보고를 배제할 수 있다. |
| **0.1 포커스 추적** | 한 환경, 로컬 작업, 기본 셸 연동. 경로 표시, 폴더 열기, 경로 복사, 잠금, 키보드 호출. | 두 폴더를 오가며 표시와 실행 대상이 일치한다. 재시작 후 설정이 유지된다. |
| **0.2 안정화·연동 확대** | 다중 창·화면, 빠른 전환, 복귀·재연결 검증. 같은 구조에 두 번째 연결 모듈 추가. | 오래된 응답이나 배경 이벤트 때문에 잘못 전환되지 않는다. 지원 조합이 명시돼 있다. |
| **0.3 프로젝트 연결** | 기준 폴더에 이름과 링크·폴더·앱 실행 대상을 연결. 매칭·편집·수동 선택. | 하위 폴더에서도 올바른 도구가 나온다. 미등록 경로는 기본 Dock으로 동작한다. |
| **이후 수요 기반 확장** | 상태 카드, 특정 TUI·Herdr·tmux 연동, 원격 경로, 데이터 카드 등. | 반복 사용과 실제 요구가 확인된 기능부터 하나씩 확장한다. |

### 첫 지원 환경을 정하는 기준

앱 이름만 고르지 말고 “터미널 + 셸 + 중첩 도구 + 로컬/원격” 조합으로 정한다. 실제 가장 많이 쓰는 조합, 포커스·경로를 읽는 방법, 설치에 필요한 권한을 함께 비교한다.

검증용 기본 후보는 Ghostty + zsh + 로컬 + 직접 분할 pane이다. Ghostty의 공식 조회 기능이 출발점이 될 수 있지만, 이것이 최종 개발 순서로 확정된 것은 아니다. [S1](#source-s1)

> **Herdr 사용 맥락을 놓치지 않는다**
>
> 실제 작업이 Herdr 내부 pane 중심이라면 바깥 터미널 연동만으로 요구를 충족했다고 판단하지 않는다. 독립 셸에서의 기술 검증과 실제 작업 환경에서의 제품 검증을 구분하고, 필요하면 내부 연결 모듈을 앞당긴다.

### 범위를 늘리는 순서

한 환경의 추적과 최소 동작 → 실사용 안정화 → 두 번째 환경 또는 프로젝트 연결 순으로 진행한다. 모든 터미널 지원을 끝내야 0.3으로 갈 수 있는 것은 아니다. 핵심 경험이 안정되면 도구 묶음의 가치도 병행 검증한다.

버전은 기간이나 출시일의 약속이 아니라 완료 범위를 구분하는 표식이다. 최소 macOS 버전, 첫 지원 앱·셸 버전은 설치본 검증 후 확정한다.

## 4. 0.1 기능 명세: 최소 Dock

목표: 프로젝트를 등록하지 않아도, 선택한 pane의 경로에 맞춰 표시와 버튼 대상이 바뀌는 작은 Dock을 만든다.

| **ID** | **필수 기능** | **완료 기준** |
| --- | --- | --- |
| **F01** | 현재 작업 정보 조회 | 지원 환경의 앱·세션·pane·경로·정보 출처·갱신 상태를 진단 화면에서 확인한다. |
| **F02** | 포커스와 경로 추적 | pane 전환과 같은 pane의 경로 변경을 모두 반영한다. 배경 pane의 보고는 전환을 일으키지 않는다. |
| **F03** | 경로 표시 | 짧은 폴더 이름을 표시하고 전체 경로를 펼쳐 확인한다. 같은 이름의 폴더를 구분할 수 있다. |
| **F04** | 폴더 열기 / 경로 복사 | 클릭 시점에 표시된 유효 경로를 사용한다. 사라진 경로나 실패는 이유를 표시한다. |
| **F05** | 자동 추적 잠금 | 현재 표시 대상을 고정한다. 해제하면 최신 포커스를 다시 조회한 뒤 반영한다. |
| **F06** | 키보드 접근 | 단축키 호출, 항목 이동·실행, 닫기를 지원한다. 기존 단축키와 충돌을 확인한다. |
| **F07** | 표시 제어와 상태 안내 | Dock 숨김·표시와 한 화면 배치를 지원한다. 추적 중·유지·잠금·연결 오류를 구분한다. |
| **F08** | 설정과 복구 | 선택한 연결 모듈, 표시 위치, 단축키를 로컬에 저장한다. 손상된 설정은 안전하게 복구한다. |

### 첫 사용 흐름

앱 실행 → 사용할 환경 선택 → 필요한 연동·권한 확인 → 진단 결과 확인 → Dock 표시. 프로젝트 이름이나 저장소를 입력하는 과정은 요구하지 않는다.

```text
[ api · 자동 ] 폴더 열기 | 경로 복사 | 잠금
보고된 경로: ~/work/shop/api · 출처: 선택된 터미널
```

다른 pane을 선택하면 버튼 위치는 유지하고, 표시 경로와 실행 대상이 함께 바뀐다. 위 표시는 정보 구조 예시이며 확정 UI 디자인은 아니다.

### 첫 버전에서 제외하는 것

네이티브 Dock 설정 변경·대체, 프로젝트 편집기, 다양한 위젯, 플러그인 스토어, 셸 명령 실행, 앱 자동 종료, 창 재배치, 계정·동기화, 원격 작업 경로는 제외한다.

검증용 최소 범위: 로컬 경로, 선택한 셸, 단일 연결 조합. 미지원 TUI 내부 상태를 정상 추적으로 표시하지 않는다.

## 5. 자동 전환 규칙과 사용자 경험

| **상황** | **제안 동작** |
| --- | --- |
| **다른 pane / 같은 pane의 경로 변경** | 현재 포커스를 확인한 후 해당 경로를 반영한다. 같은 경로면 불필요한 재배치를 하지 않는다. |
| **비활성 pane의 업데이트** | 캐시만 갱신한다. 현재 Dock의 경로·실행 대상을 바꾸지 않는다. |
| **터미널 → 브라우저·문서 앱 이동** | 마지막 유효한 작업 위치를 유지한다. 유지 상태임을 알 수 있게 표시한다. |
| **Dock 자체를 클릭하거나 호출** | Dock을 사용하기 직전의 작업 정보를 유지한다. 자기 창의 활성화를 새 작업으로 해석하지 않는다. |
| **빠른 연속 전환 / 늦은 응답** | 선택 변경 번호를 비교해 이전 응답을 버린다. 필요한 경우 짧은 안정화 시간을 둔다. |
| **마우스·키보드로 항목을 선택 중** | 상호작용이 끝날 때까지 화면 전환을 보류한다. 실행은 선택 시작 시점의 항목에 결합한다. |
| **자동 추적 잠금** | 표시 대상을 고정하되 새 정보는 별도로 갱신한다. 잠금 해제 시 포커스를 재검증한다. |
| **조회 실패·권한 거부·연결 끊김** | 마지막 위치는 과거 정보로 구분해 표시한다. 유효성을 확인할 수 없는 열기 동작은 막거나 재확인한다. |
| **지원하지 않는 환경 / 원격 경로** | 알 수 없음·미지원 상태로 표시한다. 원격 경로를 로컬 폴더로 잘못 열지 않는다. |

### 화면 상태는 원인과 함께 표시한다

추적 중: 유효한 포커스·경로가 확인됨. 유지 중: 다른 앱을 사용하면서 마지막 위치를 표시함. 잠금: 사용자가 위치를 고정함. 확인 중·연결 오류: 새 대상의 경로 또는 연결을 확인하지 못함.

“마지막 확인 시각”과 “마지막 경로 변경 시각”을 구분한다. 같은 폴더에서 오래 작업한다는 이유만으로 정보를 오래된 것으로 판단하지 않는다. 재조회·연결 상태를 기준으로 신선도를 관리한다.

### 방해하지 않는 UI

아이콘 크기와 주요 버튼 위치는 고정한다. 상태는 색만으로 전달하지 않고 텍스트·접근 가능한 이름을 함께 제공한다. 기본 Dock과 겹치지 않는 배치를 선택하고, 모든 전체화면·Spaces 조합 지원을 검증 전에 약속하지 않는다.

> **중요한 구분**
>
> 새 pane은 확인했지만 그 경로가 아직 없다면, 이전 경로를 새 pane의 경로처럼 표시하지 않는다. 이전 위치를 유지하는 경우에도 “이전 위치”라는 상태가 명확해야 한다.

## 6. 환경별 연동: 확인 사실과 검증 항목

공개 공식 문서 확인일: 2026.09.16. 아래는 API 존재 확인과 설계 후보이며, 사용자 설치본에서의 실행·정확도 검증 결과가 아니다.

| **환경** | **공식 문서에서 확인한 내용** | **우리 구현에서 검증할 부분** |
| --- | --- | --- |
| **Ghostty** | Ghostty 1.3.0부터 AppleScript를 지원한다. focused terminal과 working directory 조회 모델을 제공한다. [S1](#source-s1) | 설치 버전·자동화 승인, 셸 연동 상태, 분할·탭·창 전환과 경로 갱신의 일치 여부. |
| **cmux** | CLI·소켓, identify, surface 조회, capabilities와 surface 식별 변수를 제공한다. 기본 접근은 cmux 내부 프로세스에 제한된다. [S3](#source-s3) | 포커스된 surface와 경로의 정확한 결합, 외부 앱의 접근 방식, 버전별 응답 필드. |
| **Terminal + zsh** | zsh의 chpwd는 경로 변경 시, precmd는 프롬프트 표시 전에 실행되는 훅이다. [S4](#source-s4) | 선택된 탭과 셸/TTY 식별자의 연결. Terminal 설치본 스크립팅 사전·권한 확인. 포커스 조회 방식은 미확정. |
| **Herdr / 중첩 환경** | pane.current, 상태 조회, 이벤트 구독을 제공하며 foreground_cwd는 조회 가능한 경우에 제공된다. [S5](#source-s5) | 바깥 창과 Herdr 세션의 결합, 현재 패널과 호출 패널 구분, 내부 TUI 경로 의미·다중 클라이언트. |

### 연동별 설계 메모

Ghostty: 공식 경로 속성을 읽는 방식부터 검증한다. 셸 연동이 작업 디렉터리 관련 기능에 관여하므로 연동 상태와 중간에 셸을 바꾼 경우도 확인한다. 터미널에 pwd를 입력해 결과를 읽는 방식은 사용하지 않는다. [S1](#source-s1), [S2](#source-s2)

cmux: 기본 보안 모드를 낮추는 것을 설치 기본값으로 삼지 않는다. 필요하면 사용자 동의하에 내부 연결 프로그램이 최소 상태만 전달하는 방식을 검증한다. workspace 요약 경로를 선택된 surface의 경로로 단정하지 않는다. [S3](#source-s3) / 설계 제안

Terminal: 셸의 경로 보고와 UI의 탭 포커스는 다른 신호다. 둘을 식별자로 결합할 수 있는지 먼저 실험한다. 셸 훅만 설치해서 포커스 추적까지 완성됐다고 보지 않는다. [S4](#source-s4) / 설계 제안

> **지원 경계**
>
> 터미널의 작업 경로, 멀티플렉서의 내부 pane 경로, TUI가 자체 관리하는 프로젝트는 서로 다른 계층이다. 가장 안쪽 상태를 읽을 공식 연동이 없다면 이를 추측해서 자동 전환하지 않는다.

## 7. 기술 구조와 데이터 흐름

기술 선택안은 Swift + SwiftUI + AppKit이다. 설정·Dock 내용과 창·포커스 제어를 분리한다. 구현은 연결 모듈 하나로 시작하되, 공통 데이터 계약을 먼저 둔다.

```text
연결 모듈 → 포커스 판정 → 경로 검증 → Dock 구성 → 화면
Ghostty / cmux / Terminal → 현재 작업 정보 → 기본 동작 또는 프로젝트 도구
```

| **구성요소** | **역할** |
| --- | --- |
| **Adapter** | 환경별 조회·연결·권한 상태를 공통 정보로 변환한다. UI를 직접 변경하지 않는다. |
| **FocusResolver** | 현재 macOS 작업 대상과 내부 pane을 연결한다. 배경 신호와 늦은 응답을 제외한다. |
| **ContextStore** | 최신 작업 정보, 연결 상태, 잠금·유지 상태를 관리한다. 영구 설정과 런타임 캐시는 분리한다. |
| **DockComposer** | 0.1은 공통 동작을 생성한다. 0.3은 프로젝트 매칭 결과로 도구 구성을 생성한다. |
| **ActionRouter** | 사용자가 선택한 항목과 경로를 고정한 뒤 실행한다. 실패·미지원·권한 문제를 일관되게 처리한다. |

### 현재 작업 정보의 최소 필드

| **필드 묶음** | **내용** |
| --- | --- |
| **식별** | adapterID, appID, windowID, sessionID, paneID, machineID. 원본 식별자를 보존하고 충돌을 피한다. |
| **경로** | reportedCWD, normalizedCWD, cwdSource. 표시용 원본과 비교용 값을 구분한다. |
| **신선도·순서** | observedAt, focusGeneration, sourceSequence. 시각만으로 다른 세션의 순서를 섞지 않는다. |
| **유효성** | focusStatus, pathStatus, connectionStatus. 아직 모름과 조회 실패, 이전 위치 유지를 구분한다. |

### 순서 역전과 오작동 방지

포커스가 바뀌면 선택 변경 번호를 올린다. 경로 조회 응답에는 요청 당시의 번호·대상 ID를 붙이고, 현재 선택과 다르면 버린다. 앱·pane·경로·상태는 하나의 일관된 묶음으로 화면에 적용한다.

연결 모듈이 이벤트를 제공하면 활용하고, 그렇지 않으면 제한된 주기의 재조회로 시작한다. 숨김·비활성 상태에서는 불필요한 조회를 줄이되 복귀할 때 즉시 검증한다. 조회 실패가 UI 전체를 멈추지 않도록 분리한다.

설정에는 스키마 버전을 둔다. 프로젝트 모델은 나중에 추가하되, DockComposer 앞에 매칭 단계를 붙일 수 있도록 감지 로직과 저장 구조를 분리한다.

## 8. 0.3 확장: 프로젝트별 도구 묶음

이 단계는 제품의 방향 전환이 아니다. 자동 추적은 그대로 유지하고, 감지한 경로를 사용자가 등록한 프로젝트와 연결한다.

| **초기 0.1** | **프로젝트 연결 이후 0.3** |
| --- | --- |
| **현재 경로 → 공통 동작의 대상 변경** | 현재 경로 → 프로젝트 판별 → 프로젝트 도구 표시 |
| **프로젝트 등록 없이 사용** | 등록한 프로젝트만 더 풍부하게 표시 |
| **폴더 열기 / 경로 복사** | 저장소 / 문서 / 디자인 / 미리보기 / 폴더 / 앱 대상 |

### 프로젝트 데이터와 설정 흐름

프로젝트는 고유 ID, 표시 이름, 기준 경로, 머신 구분, 항목 순서, 각 항목의 종류·실행 대상을 가진다. 첫 확장에서는 “현재 폴더에 도구 연결”로 진입해 링크 하나부터 추가할 수 있게 한다.

```text
[ Shop · 자동 ] 저장소 | 디자인 | 개발 페이지 | 폴더
기준 폴더: ~/work/shop / 현재 위치: ~/work/shop/api
```

### 경로 매칭 규칙

| **규칙** | **제안 동작** |
| --- | --- |
| **가장 구체적인 경로 우선** | ~/work/shop과 ~/work/shop/admin이 등록돼 있으면 admin/src는 Admin 프로젝트에 연결한다. |
| **폴더 단위로 비교** | 단순 문자열 접두사로 비교하지 않는다. shop-old는 shop에 포함되지 않는다. |
| **원본 경로 보존** | 표시 경로는 보고값을 보존한다. 심볼릭 링크·대소문자 비교 정책은 테스트해 확정하고, 무조건 소문자로 바꾸지 않는다. |
| **미등록 경로** | 공통 동작을 제공하는 기본 Dock으로 돌아간다. 프로젝트 등록을 강요하지 않는다. |
| **수동 선택·잠금 우선** | 사용자가 고른 프로젝트를 고정할 수 있다. 자동 모드로 돌아갈 때는 최신 포커스를 다시 확인한다. |

### 앱 자체보다 실행 대상을 연결한다

프로젝트가 달라도 같은 브라우저와 터미널을 쓸 수 있다. 따라서 아이콘만 바꾸는 것보다 해당 저장소·문서·페이지를 여는 것이 중요하다. 폴더·URL·앱 실행은 명시적으로 구분하고, 앱별 프로젝트 열기 지원 범위도 따로 관리한다.

> **프로젝트 연결 단계의 성공 기준**
>
> “Dock이 바뀐다”를 넘어 “현재 프로젝트의 문서·저장소·페이지를 다시 찾을 일이 줄었다”가 확인돼야 한다. 자동 전환으로 앱을 열거나 서버를 실행하지는 않는다.

## 9. 권한·보안·개인정보·배포 원칙

### 필요한 상태만 읽는다

초기 데이터는 앱·pane 식별자, 작업 경로, 포커스·연결 상태로 제한한다. 터미널 화면, 명령 이력, 입력 내용, 소스 파일 내용은 수집하지 않는다. 화면 OCR이나 키 입력 감시로 경로를 추정하지 않는다.

| **영역** | **제품의 기본 원칙** |
| --- | --- |
| **앱 간 자동화** | Ghostty의 AppleScript 연동에는 macOS 자동화 승인이 적용된다. 권한 거부 시 기능 상태와 해결 경로를 안내한다. [S1](#source-s1) |
| **셸 연동 설치** | 사용자 동의를 받고 최소 연동만 설치한다. 기존 훅을 덮어쓰지 않고 제거·복구 방법을 함께 제공한다. |
| **소켓·연결 프로그램** | 기본 접근 제한을 유지하는 설계를 우선한다. cmux의 allowAll 설정을 자동으로 켜지 않는다. [S3](#source-s3) |
| **로컬 통신** | 앱 전용 사용자 범위에서 통신하고 상대 식별·메시지 크기·형식을 검증한다. 같은 사용자 프로세스도 무조건 신뢰하지 않는다. |
| **경로와 실행** | 경로를 실행 코드로 해석하지 않는다. 공백·따옴표·제어 문자를 안전하게 처리하고, 문자열을 셸 명령으로 조합하지 않는다. |
| **개인정보** | 작업 경로는 기본적으로 로컬에서만 처리한다. 진단 내보내기 전 전체 경로·세션 식별자 제거 또는 가림을 적용한다. |
| **확장 기능** | 스크립트·플러그인 실행, 원격 명령, 외부 계정 토큰은 초기 범위에 포함하지 않는다. |

### 권한은 기능별로 검증한다

초기 제품은 접근성·화면 기록·전체 디스크 접근을 기본 전제에 두지 않는 범위로 설계한다. 다만 파일 접근, 창 동작, 단축키 및 자동화의 실제 권한 요구는 배포 형태와 설치 환경에서 각각 검증한다. “경로를 알 수 있음”과 “그 파일을 읽을 수 있음”을 혼동하지 않는다.

### 배포와 운영

개인 실사용 검증 이후 외부 베타에서는 Developer ID 서명과 Apple 공증을 통한 직접 배포를 우선 검토한다. Apple은 Mac App Store 외부 배포를 위한 서명·공증 절차를 제공한다. [S6](#source-s6)

직접 배포와 샌드박스 적용 여부는 별도 결정 사항이다. 업데이트·삭제·셸 연동 제거·권한 회수 후 상태를 테스트하고, 자동 로그인 실행은 사용자가 선택하도록 한다.

기본값 제안: 계정 없음, 클라우드 동기화 없음, 원격 분석 전송 없음. 추후 사용성 지표가 필요해도 경로·명령·프로젝트 내용을 보내지 않는 방식을 우선 검토한다.

## 10. 검증 계획과 출시 판단 기준

검증은 기술 정확도와 제품 유용성을 분리한다. 아래 기준은 목표이며 측정 결과가 아니다. 현재 macOS 실기기 테스트는 수행하지 않았다.

| **검증 시나리오** | **기대 결과** |
| --- | --- |
| **T01 A pane → B pane** | 앱·pane·경로가 하나의 묶음으로 B에 바뀌며 A의 늦은 응답은 반영되지 않는다. |
| **T02 같은 pane에서 cd** | 연동 소스가 새 경로를 보고하면 Dock 표시와 실행 대상이 함께 바뀐다. |
| **T03 비활성 pane에서 cd** | 현재 Dock이 바뀌지 않는다. 해당 pane을 선택한 시점에만 반영한다. |
| **T04 빠른 연속 전환** | 최종 포커스를 따른다. 잘못된 경로가 정상 상태로 남지 않는다. |
| **T05 창·탭·앱 전환** | 다른 터미널 창과 브라우저 이동을 구분하고, Dock 자체 클릭은 작업 포커스를 잃지 않는다. |
| **T06 클릭·단축키 도중 갱신** | 실행 대상은 선택 당시 항목과 일치한다. 실행 직전에 다른 프로젝트로 바뀌지 않는다. |
| **T07 경로 삭제·비정상 문자** | 오류를 설명하고 충돌하지 않는다. 공백·한글·따옴표 경로도 명령으로 해석하지 않는다. |
| **T08 연결·권한·프로세스 종료** | 추적 오류를 표시한다. 재연결 후 새 스냅샷을 확인하고, 이전 연결의 응답을 새 상태로 오인하지 않는다. |
| **T09 잠자기·화면 연결 변경** | 창이 화면 밖에 남지 않고 현재 작업 정보를 다시 확인한다. |
| **T10 잠금·유지·해제** | 고정 상태와 자동 상태가 분명하고, 해제 시 최신 포커스를 반영한다. |
| **T11 중첩 TUI·원격 환경** | 지원하지 않는 안쪽 경로를 안다고 표시하지 않는다. 원격 경로를 로컬로 오인하지 않는다. |
| **T12 프로젝트 매칭(0.3)** | 하위 폴더·중첩 등록·미등록 경로·동명 폴더가 명시된 규칙대로 동작한다. |

### 단계별 완료 판단

0.1: 지원 조합의 필수 시나리오 통과, 폴더 열기·경로 복사 정확성, 수동 잠금·오류 안내를 확인한다. 잘못된 대상으로 실행되는 오류는 출시 차단 항목이다.

0.2: 여러 창·복귀·장시간 사용에서 안정성을 확인한다. 조회 지연과 CPU·메모리를 기록하고, 숨김 상태의 불필요한 조회·누적 사용량을 점검한다.

0.3: 실제 프로젝트 두 개 이상에서 반복 사용해 문서·페이지를 찾는 단계가 줄었는지 확인한다. Dock을 켜두는 시간만으로 유용성을 판단하지 않는다.

반응성 초기 목표안: 지원된 로컬 환경에서 소스가 새 상태를 제공한 뒤 화면 반영까지 95백분위 700ms 이내. 상호작용으로 전환을 보류한 구간은 별도 기록한다. 미측정 목표이며 기술 검증 후 조정한다.

## 11. 개발 착수 항목과 미확정 결정

| **순서** | **착수 항목** | **산출물** |
| --- | --- | --- |
| **1** | 실사용 조합·설치 버전·권한 확인 | 첫 지원 조합과 제외 범위가 적힌 호환성 기록 |
| **2** | 현재 앱·pane·경로 읽기 실험 | 소스·식별자·확인 시각을 보여주는 진단 화면 |
| **3** | 공통 작업 정보와 포커스 판정 구현 | 배경 이벤트·늦은 응답을 재현하는 자동 테스트 |
| **4** | 최소 Dock과 명시적 실행 연결 | 경로 표시, 폴더 열기, 경로 복사, 잠금, 키보드 호출 |
| **5** | 오류·복귀·설정 저장 검증 | 재현 절차와 실제 측정값이 포함된 검증 기록 |
| **6** | 개인 실사용 후 다음 범위 결정 | 두 번째 연결 모듈 또는 프로젝트 연결의 우선순위 |

### 이름 후보

| **이름** | **의미와 판단** |
| --- | --- |
| **PaneDock / 페인독** | 포커스된 pane을 따라가는 Dock. 현재 목표를 직접 설명하므로 문서의 가칭으로 사용한다. |
| **HereDock / 히어독** | 지금 작업하는 위치를 강조한다. 향후 터미널 외부로 확장할 때 덜 제한적인 후보. |
| **CWDock / 시더블유독** | CWD와 Dock의 결합. 개발자 도구의 의미는 강하지만 발음·전달이 다소 어렵다. |
| **DirDock / 디어독** | Directory 기반 제품임을 표현한다. 포커스를 따른다는 특징은 추가 설명이 필요하다. |
| **FollowDock / 팔로독** | 작업을 따라온다는 동작이 직관적이다. 다른 후보보다 이름이 길다. |

이름은 아이디어 후보이며 상표·도메인·저장소명 사용 가능 여부를 조사·확정한 결과가 아니다. 공개 배포 전에 별도 확인한다.

### 아직 결정하지 않은 것

첫 지원 조합과 최소 OS·앱 버전, 배포 형태·샌드박스, 기본 단축키·화면 배치, 갱신 간격, 심볼릭 링크 정책, 최종 이름, 가격·라이선스는 미확정이다. 첫 실험 결과를 바탕으로 결정한다.

> **개발 중 범위가 커질 때의 판단 질문**
>
> 이 기능이 “포커스된 작업 위치를 정확히 따른다” 또는 “그 위치에서 필요한 대상을 더 빨리 연다”에 직접 기여하는가? 아니라면 첫 버전에서는 미룬다.

가칭 태그라인: 작업 위치가 바뀌면, Dock도 함께.

## 12. 참고 자료와 문서 사용 기준

외부 기능에 대한 사실은 아래 공식 문서를 기준으로 정리했다. 본문의 \[S번호\]는 해당 자료를 가리킨다. 설계 제안과 로드맵은 이 대화에서 정리한 제품 방향을 바탕으로 작성했다.

<a id="source-s1"></a>

**[S1]** [Ghostty 공식 문서 · AppleScript (macOS)](https://ghostty.org/docs/features/applescript)

지원 도입 버전, 창·탭·터미널 객체, focused terminal·working directory, 자동화 승인.

<a id="source-s2"></a>

**[S2]** [Ghostty 공식 문서 · Shell Integration](https://ghostty.org/docs/features/shell-integration)

셸 연동과 작업 디렉터리 관련 기능, 셸 전환 시 연동 상태에 대한 주의 사항.

<a id="source-s3"></a>

**[S3]** [cmux 공식 문서 · CLI Reference](https://cmux.com/docs/api)

CLI·소켓, identify·capabilities·surface 관련 명령, 식별 환경변수, 기본 소켓 접근 제한.

<a id="source-s4"></a>

**[S4]** [zsh 공식 매뉴얼 · Functions](https://zsh.sourceforge.io/Doc/Release/Functions.html)

chpwd와 precmd 훅의 실행 시점. 포커스 판정 기능의 근거는 아니다.

<a id="source-s5"></a>

**[S5]** [Herdr 공식 문서 · Socket API](https://herdr.dev/docs/socket-api/)

활성 pane 조회, 상태·이벤트 연동, 조회 가능한 경우의 foreground_cwd, 설치본 스키마 확인.

<a id="source-s6"></a>

**[S6]** [Apple Developer · Signing your apps for Gatekeeper](https://developer.apple.com/developer-id/)

Developer ID 서명과 외부 배포 소프트웨어의 공증 절차.

### 검증 수준과 한계

공식 문서 열람으로 연동 기능의 존재를 확인했지만, 사용자 기기의 설치 버전·권한·셸 설정과 다중 창·중첩 TUI의 실제 동작은 확인하지 않았다. 따라서 “지원 예정”과 “실제 지원 확인”을 분리해 관리해야 한다.

특히 Terminal의 선택된 탭과 셸 보고 경로를 연결하는 방식, cmux의 활성 surface별 경로 정확성, Herdr와 바깥 창의 연결은 구현 전 검증 항목이다. 특정 TUI의 내부 경로를 전부 자동 추적할 수 있다는 약속은 포함하지 않는다.

### 문서 변경 원칙

기술 검증 결과가 나오면 지원 조합, 권한, 데이터 출처, 반응성 측정값과 알려진 한계를 함께 갱신한다. 제품 방향은 유지하되 구현 수단과 단계별 범위는 근거에 따라 조정한다.

> **최종 방향**
>
> 포커스 추적으로 시작한다. 신뢰할 수 있게 만든다.  
> 그다음, 프로젝트에 필요한 도구를 연결한다.
